# beauty-miniapp — Telegram Mini App для записи в салон

Клиентское приложение платформы Beauty Salon: витрина услуг и мастеров,
онлайн-запись, магазин, лояльность и профиль — всё внутри Telegram.

Разработка — **G&D Digital Lab** (gddlab.ru).

> **Часть системы из двух репозиториев:**
> - **`beauty-miniapp`** (этот репозиторий) — клиентское приложение.
> - **`gd-salon-crm`** — CRM, API и бэкенд. Это приложение обращается к его
>   API и не работает с базой напрямую (кроме публичного чтения каталога).

## Роль в системе

```
┌─────────────────┐     initData      ┌──────────────────┐
│  beauty-miniapp  │  ───────────────► │  gd-salon-crm     │
│  (этот репо)     │   API-запросы     │  (CRM + API)      │
│  в Telegram      │ ◄───────────────  │                   │
└─────────────────┘    JSON            └──────────────────┘
```

Приложение открывается **внутри Telegram** — кнопкой-меню бота или из
приветствия на `/start`. Клиент видит витрину, записывается, покупает.
Все операции идут через API CRM; личность клиента подтверждается подписью
Telegram (`initData`).

## Функциональность

- **Онлайн-запись** — выбор услуги, мастера и свободного времени в пару
  касаний, без звонков.
- **Каталог** — категории и подкатегории с изображениями, услуги,
  портфолио мастеров, рейтинги и отзывы.
- **Корзина** — запись сразу на несколько услуг и покупка товаров в одном
  заказе.
- **Мои записи** — просмотр, отмена, самостоятельный перенос визита.
- **Лояльность** — накопление и списание баллов (кэшбэк), история.
- **Магазин** — покупка товаров/косметики и подарочных сертификатов.
- **Мои сертификаты** — купленные сертификаты с кодами активации.
- **Мои товары** — история покупок.
- **Лист ожидания** — встать в очередь на занятое время, получить
  уведомление при освобождении.
- **Избранное** — сохранение услуг и мастеров.
- **Отзывы** — оставить отзыв после визита, просмотр своих отзывов.
- **Кабинет мастера** — для сотрудников: своё расписание, записи и доход
  (привязка аккаунта через отдельный экран).

## Как устроен доступ к данным

Два канала:

1. **Через API CRM** (основной) — запись, магазин, профиль, лояльность,
   всё персональное. Запросы идут на `${VITE_API_URL}/api/...` и несут
   `initData`. База напрямую **не читается** — данные отдаёт сервер CRM
   после проверки личности.

2. **Публичное чтение каталога** (Supabase напрямую) — витрина: активные
   услуги, категории, мастера, одобренные отзывы, товары в продаже. Это
   неперсональные данные, открытые политиками RLS для чтения.

Идентификатор клиента в теле запросов **не передаётся** — сервер
устанавливает личность сам по подписи Telegram. Это защищает от доступа
к чужим данным.

## Авторизация

Личность клиента = **Telegram `initData`**:

1. Telegram при открытии Mini App формирует `initData` — подписанный пакет
   (id, имя, username, дата) с криптографической подписью.
2. Приложение передаёт `initData` в каждый запрос к API.
3. Сервер CRM проверяет подпись (`validateInitData`) своим токеном бота и
   извлекает `user.id`.

Подделать `initData` без токена бота невозможно, поэтому серверу можно
доверять личности. Приложение не хранит паролей и токенов доступа.

> Открывать Mini App нужно **кнопкой** (меню бота или приветствие
> `/start`) — только так Telegram передаёт корректный `initData`.

## Разработка и сборка

```bash
npm install
npm run dev       # dev-сервер Vite
npm run build     # tsc -b && vite build
npm run preview   # предпросмотр сборки
npm run lint      # eslint
```

Для локальной работы с Telegram Mini App укажите `VITE_API_URL` на
работающий CRM и открывайте приложение через тестового бота (иначе
`initData` будет пустым).

## Развёртывание

Хостинг — **Vercel**, автодеплой из `main`.

1. `npm run build` — проверка сборки.
2. `git push` → Vercel деплоит.
3. Убедиться, что `VITE_API_URL` в переменных Vercel указывает на актуальный
   адрес CRM.

Полученный адрес приложения прописывается боту как **Menu Button**
(в @BotFather) и в `WEBAPP_URL` на стороне CRM — чтобы кнопки открывали
именно его.
